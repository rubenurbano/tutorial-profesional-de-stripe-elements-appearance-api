Tutorial Profesional de Stripe Elements: Appearance API by Rubén Sbarsky

Domina la personalización visual del Payment Element de Stripe desde cero hasta una arquitectura profesional en Windows 11, Node.js, Express y Stripe.js.

Nivel: Desde cero a profesional Entorno: Windows 11 · VS Code · Node.js LTS · Express Fecha contraste: 24/11/2026
Aviso de vigencia: Este curso se ha contrastado con la documentación oficial de Stripe consultada el 24/11/2026. La documentación web puede cambiar. Antes de desplegar una integración comercial, vuelve a comprobar los enlaces oficiales de la pestaña Fuentes.

1. Qué vamos a aprender

Objetivo

Al terminar podrás personalizar el aspecto del Payment Element de Stripe para que combine con la identidad visual de una web: colores, tipografía, espaciado, bordes, etiquetas y estados permitidos por Stripe.

No necesitas saber programar. Aprenderás lo suficiente de HTML, CSS, JavaScript, terminal y servidor para entender y modificar un proyecto real de demostración.

Resultado concreto

Construirás una página de pago de prueba llamada Taller Demo que:

  1. Se ejecuta en tu ordenador con Windows 11.
  2. Solicita a un pequeño servidor la creación de un PaymentIntent de prueba.
  3. Muestra el Payment Element de Stripe.
  4. Aplica una configuración Appearance API.
  5. Permite comparar temas y modificar variables y reglas.
  6. Confirma un pago de prueba sin mover dinero real (importe fijo de demostración: 24,99 EUR).

Herramientas necesarias

  • Windows 11.
  • Un navegador actualizado (Edge, Chrome o Firefox).
  • Visual Studio Code.
  • Node.js en versión LTS.
  • Una cuenta de Stripe y un entorno de pruebas (sandbox).
  • Conexión a Internet.

Qué queda fuera del alcance

No construiremos una tienda completa, un sistema de inventario, facturación, suscripciones, impuestos, gestión de clientes, panel administrativo ni despliegue productivo. Tampoco certificaremos el cumplimiento normativo o PCI de un negocio. El proyecto enseña la integración básica necesaria para comprender Appearance API; no es una solución comercial lista para producción.

Actividad inicial: Escribe en una nota qué marca ficticia te gustaría diseñar y qué tres colores la representarían.
Comprobación: Debes poder explicar con tus palabras el resultado que vas a construir y distinguir entre personalizar el formulario y desarrollar todo un sistema de comercio electrónico.

2. Stripe explicado desde cero

2.1. ¿Qué es Stripe?

Stripe es una plataforma de infraestructura de pagos. Permite a empresas aceptar pagos en sitios web y aplicaciones, gestionar métodos de pago y consultar operaciones desde un panel llamado Dashboard. Detrás de un pago hay una operación coordinada entre el navegador, el servidor de la empresa y los sistemas de Stripe.

2.2. ¿Qué es Stripe Elements?

Stripe Elements es una colección de componentes de interfaz preparados por Stripe para recoger información de pago (formulario de tarjeta, selector de métodos de pago o campo de dirección). La ventaja es que no tienes que programar desde cero la captura y validación de los datos sensibles de la tarjeta: Stripe aloja los campos sensibles en componentes seguros.

2.3. ¿Qué es un Element?

Un Element es uno de esos componentes individuales. Por ejemplo, el Payment Element es un componente que puede mostrar varios métodos de pago disponibles para el cliente.

2.4. ¿Qué es Payment Element?

Payment Element es un componente integrable en una web. Puede mostrar distintos métodos de pago, adaptar las opciones según la configuración de la cuenta y el contexto, validar entradas y presentar mensajes de error. No lo confundas con Stripe Checkout:

  • Payment Element: componente integrado dentro de tu propia página. Tú construyes la experiencia que lo rodea.
  • Stripe Checkout: experiencia de checkout de Stripe, alojada o integrada según la modalidad elegida. Tiene otro modelo de integración y personalización.

2.5. ¿Qué es Stripe.js?

Stripe.js es la biblioteca JavaScript de Stripe para el navegador. Permite inicializar Stripe, crear Elements, mostrar componentes y confirmar pagos desde el cliente. No sustituye al servidor: el navegador nunca debe contener la clave secreta de Stripe.

2.6. ¿Qué es Appearance API?

Es la interfaz de configuración que permite definir cómo se ven determinados Elements compatibles. Se pasa como opción appearance al crear la instancia de Elements. Piensa en un automóvil: Stripe proporciona el sistema de seguridad y los mecanismos internos del formulario; Appearance API te permite elegir parte de su acabado exterior, sin desmontar el motor.

Término importante — PaymentIntent: Es el objeto de Stripe que representa el intento de realizar un pago y su ciclo de vida. El servidor crea el PaymentIntent y determina el importe. El navegador recibe su client_secret, que permite completar ese pago concreto. No es una clave secreta de cuenta, pero tampoco debe registrarse ni compartirse públicamente.

3. Qué significa personalizar la apariencia

  • Tema (theme): Base visual predefinida. Stripe ofrece stripe, night y flat.
  • Variables (variables): Valores generales que afectan a muchas partes del Element (colorPrimary, colorBackground, colorText, fontFamily, borderRadius, spacingUnit). Pertenecen al sistema de apariencia de Stripe, no son reglas CSS globales.
  • Reglas (rules): Ajustan componentes concretos mediante selectores públicos documentados (.Input, .Label, .Tab, .Input:focus). Propiedades en camelCase: boxShadow, no box-shadow.
  • Selectores: Identifican una parte pública del Element. No inventes selectores ni dependas de clases privadas.
  • Estados visuales: Normal, enfocado, deshabilitado o inválido. No todos los estados existen para todas las clases.
  • Diseño adaptable: El Payment Element se adapta a distintos tamaños de pantalla, pero tu página también debe ser responsive.

3.8. ¿Qué controla Stripe y qué controla tu web?

Zona Quién la controla Ejemplos
Exterior del formulario Tu CSS Ancho del contenedor, márgenes de página, fondo general, título y textos propios
Interior del Payment Element Appearance API y Stripe Variables, reglas y componentes públicos admitidos
Datos sensibles de pago Stripe Elements Campos de pago gestionados por Stripe (iframes seguros)
Importe y lógica de pedido Tu servidor Precio, moneda, condiciones comerciales

4. Qué se puede hacer y qué no

Personalización ¿Permitida? Observaciones
Elegir stripe, night o flat Sí Temas documentados
Color principal y de fondo Sí Mediante variables compatibles
Tipografía Sí fontFamily y opción fonts para fuentes personalizadas
Tamaño base del texto Sí fontSizeBase; Stripe recomienda al menos 16 px para campos en móvil
Radio de bordes y espaciado Sí borderRadius, spacingUnit y variables relacionadas
Estilo de .Input o .Tab Sí Solo clases y propiedades admitidas
Cambiar el orden interno arbitrariamente No La disposición general del Element se mantiene consistente
Usar selectores privados o cualquier CSS No Solo nombres públicos y propiedades admitidas por clase
Aplicar Appearance API a CardElement No Elements individuales usan el objeto Style, no Appearance API
Rediseñar la lógica del pago No Es responsabilidad de integración, no de apariencia
Distinción esencial: La guía de Appearance API consultada cubre integraciones de Elements con Payment Intents. Si utilizas Elements con Checkout Sessions, consulta su documentación específica. Aunque Stripe recomienda Checkout Sessions con Payment Element para la mayoría de integraciones nuevas, aquí utilizamos Payment Intents porque permite estudiar el flujo completo y controlar el importe y la lógica desde nuestro propio servidor.

9 y 10. Código completo de la primera integración

El frontend (HTML, CSS y JS) carga https://js.stripe.com/v3/, solicita el clientSecret al endpoint /create-payment-intent del backend y monta el Payment Element con la configuración appearance.

10.1. server.mjs (Backend)

server.mjs 
import 'dotenv/config';
import express from 'express';
import Stripe from 'stripe';

const app = express();
const port = Number(process.env.PORT || 4242);
const secretKey = process.env.STRIPE_SECRET_KEY;

if (!secretKey || !secretKey.startsWith('sk_test_')) {
  throw new Error(
    'Falta STRIPE_SECRET_KEY de pruebas. Revisa el archivo .env.'
  );
}

const stripe = new Stripe(secretKey);

app.use(express.static('public'));
app.use(express.json());

app.post('/create-payment-intent', async (req, res) => {
  try {
    // Importe fijado en el servidor: 24,99 EUR = 2499 céntimos.
    const paymentIntent = await stripe.paymentIntents.create({
      amount: 2499,
      currency: 'eur',
      automatic_payment_methods: {
        enabled: true
      }
    });

    res.json({
      clientSecret: paymentIntent.client_secret
    });
  } catch (error) {
    console.error('No se pudo crear el PaymentIntent:', error.message);
    res.status(500).json({
      error: 'No se pudo preparar el pago de prueba.'
    });
  }
});

app.listen(port, () => {
  console.log(`Servidor de prueba disponible en http://localhost:${port}`);
});

10.4. public/app.js

public/app.js 
const publishableKey = 'pk_test_REEMPLAZA_POR_TU_CLAVE_PUBLICABLE';

const stripe = Stripe(publishableKey);

const appearance = {
  theme: 'stripe',
  inputs: 'spaced',
  labels: 'above',
  variables: {
    colorPrimary: '#147d69',
    colorBackground: '#ffffff',
    colorText: '#172b36',
    colorDanger: '#b4233c',
    fontFamily: 'Arial, Helvetica, sans-serif',
    fontSizeBase: '16px',
    spacingUnit: '4px',
    borderRadius: '10px',
    inputColorBorder: '#cbd9d9',
    inputFocusColorBorder: '#147d69'
  },
  rules: {
    '.Input': {
      boxShadow: 'none'
    },
    '.Input:focus': {
      boxShadow: '0 0 0 2px rgba(20, 125, 105, 0.18)'
    },
    '.Label': {
      fontWeight: '600'
    },
    '.Tab--selected': {
      boxShadow: '0 0 0 2px var(--colorPrimary)'
    }
  }
};

const form = document.querySelector('#payment-form');
const button = document.querySelector('#submit-button');
const buttonText = document.querySelector('#button-text');
const message = document.querySelector('#payment-message');

let stripeElements;

function showMessage(text) {
  message.textContent = text;
}

async function initialize() {
  try {
    const response = await fetch('/create-payment-intent', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      }
    });

    const data = await response.json();

    if (!response.ok) {
      throw new Error(data.error || 'No se pudo iniciar el pago.');
    }

    stripeElements = stripe.elements({
      clientSecret: data.clientSecret,
      appearance
    });

    const paymentElement = stripeElements.create('payment');
    paymentElement.mount('#payment-element');

    button.disabled = false;
    buttonText.textContent = 'Pagar 24,99 € (prueba)';
  } catch (error) {
    showMessage(error.message);
    buttonText.textContent = 'No disponible';
  }
}

form.addEventListener('submit', async (event) => {
  event.preventDefault();

  if (!stripeElements) return;

  button.disabled = true;
  buttonText.textContent = 'Procesando…';
  showMessage('');

  const { error, paymentIntent } = await stripe.confirmPayment({
    elements: stripeElements,
    confirmParams: {
      return_url: `${window.location.origin}/`
    },
    redirect: 'if_required'
  });

  if (error) {
    showMessage(error.message || 'No se pudo confirmar el pago.');
    button.disabled = false;
    buttonText.textContent = 'Intentar de nuevo';
    return;
  }

  if (paymentIntent && paymentIntent.status === 'succeeded') {
    showMessage('Pago de prueba completado correctamente.');
    buttonText.textContent = 'Pago completado';
    return;
  }

  showMessage('La operación se ha enviado. Comprueba su estado en Stripe.');
  buttonText.textContent = 'Operación enviada';
});

initialize();

11 y 12. Configuración de apariencia y Temas

El objeto appearance se entrega a stripe.elements({ clientSecret, appearance }). Contiene theme ('stripe', 'night', 'flat'), inputs ('spaced' o 'flat'), labels ('above' o 'floating'), variables y rules.

13. Variables principales

Restricción importante de sintaxis: Las variables colorPrimary, colorBackground, colorText, colorSuccess, colorDanger y colorWarning no admiten rgba() ni var(--myVariable) como valor directo. Utiliza valores hexadecimales o RGB sólidos.
Categoría Variables documentadas Notas
Colores generales colorPrimary, colorBackground, colorText, colorTextSecondary, colorTextPlaceholder, colorDanger, colorSuccess, colorWarning Controlan la paleta global
Tipografía fontFamily, fontSizeBase, fontSize2Xl..fontSize3Xs, fontWeightLight, fontWeightNormal, fontWeightMedium, fontWeightBold, fontLineHeight, fontSmooth Stripe recomienda fontSizeBase: '16px' mínimo en móviles
Bordes, campos y foco borderRadius, spacingUnit, inputColorBorder, inputBoxShadow, inputFocusColorBorder, inputFocusBoxShadow, focusBoxShadow, focusOutline Base geométrica y anillos de foco
Etiquetas y botones labelColorText, labelFontSize, labelFontWeight, labelSpacing, buttonBorderRadius, buttonBoxShadow, buttonColorBackground, buttonColorText labelSpacing no aplica en etiquetas flotantes
Iconos y pestañas iconColor, iconHoverColor, iconCheckmarkColor, tabIconColor, tabIconSelectedColor, tabSpacing, accordionItemSpacing, gridRowSpacing Ajustes de navegación interna

14, 15, 16 y 17. Reglas, Fuentes, Accesibilidad y Marca

  • Selectores válidos: .Tab, .Label, .Input, .Tab:focus, .Tab--selected, .Input--invalid, .Label--invalid, .Input::placeholder, .Block, .Checkbox, .Dropdown, .Switch, .PickerItem, .Menu, .AccordionItem.
  • Selectores prohibidos: Clases privadas (.p-SomePrivateClass), etiquetas genéricas (img), selectores descendientes (.Tab .TabLabel) o estados no documentados (.Tab--invalid).
  • Fuentes personalizadas: Se cargan pasando la opción fonts a stripe.elements({ clientSecret, appearance, fonts }) y referenciándolas en variables.fontFamily.
  • Accesibilidad: Garantiza contraste adecuado, fontSizeBase de al menos 16 px en móvil, indicadores de foco visibles para teclado (Tab, Mayús + Tab) y mensajes de error claros sin depender solo del color rojo.

Parte VII. 33 Preguntas y Respuestas

Ordenadas progresivamente por nivel de dificultad: Nivel 1 (Principiante), Nivel 2 (Intermedio) y Nivel 3 (Avanzado).

Nivel 1 — Principiante (Preguntas 1 a 11)

1. ¿Qué es Stripe Elements?
Es una colección de componentes de interfaz preparados por Stripe para integrar formularios y datos de pago en una web. Evita que tengas que programar desde cero todos los campos sensibles.
2. ¿Qué hace Appearance API?
Permite personalizar la apariencia de Elements compatibles: temas, colores, fuentes, bordes, espaciado y reglas para componentes públicos. No crea el pago ni sustituye la lógica del servidor.
3. ¿Qué diferencia hay entre Stripe.js y Elements?
Stripe.js es la biblioteca JavaScript que permite utilizar Stripe desde el navegador. Elements es el sistema de componentes que se crea y gestiona con esa biblioteca.
4. ¿Qué es Payment Element?
Es un componente que puede presentar varios métodos de pago en una sola interfaz integrada en la web.
5. ¿Necesito saber programar para utilizarlo?
Para utilizarlo en un proyecto real sí necesitas aprender conceptos básicos o trabajar con alguien que los domine. Este curso parte de cero, pero no convierte una integración de pagos en una operación sin conocimientos técnicos.
6. ¿Puedo cambiar el color principal?
Sí. Puedes utilizar colorPrimary dentro de variables. Comprueba el contraste y recuerda que no todos los componentes necesariamente muestran ese color del mismo modo.
7. ¿Qué temas ofrece Stripe?
La documentación de Appearance API consultada enumera stripe, night y flat.
8. ¿Puedo usar mi propia tipografía?
Sí. Puedes definir fontFamily y, si necesitas cargar una fuente personalizada, proporcionar la opción fonts al crear Elements, siguiendo la documentación de Stripe.js.
9. ¿Qué diferencia hay entre CSS y Appearance API?
CSS controla tu página y sus contenedores. Appearance API controla los estilos de los componentes Stripe compatibles. Los campos seguros no se comportan como elementos HTML normales de tu documento.
10. ¿Qué es la clave publicable?
Es una clave identificada por el prefijo pk_. Stripe permite exponerla en el navegador para inicializar Stripe.js y Elements. No tiene los permisos de una clave secreta.
11. ¿Puedo probar sin cobrar dinero?
Sí. Utiliza un sandbox y claves de prueba. Stripe ofrece tarjetas de prueba para simular operaciones. No introduzcas datos de tarjetas reales.

Nivel 2 — Intermedio (Preguntas 12 a 22)

12. ¿Dónde se pasa el objeto appearance?
Al crear la instancia Elements, por ejemplo stripe.elements({clientSecret, appearance}). No se pasa como una hoja CSS ni como argumento de mount.
13. ¿Qué diferencia hay entre variables y reglas?
Las variables son valores generales que afectan a varias partes. Las reglas permiten ajustar selectores públicos concretos y sus estados admitidos.
14. ¿Puedo escribir cualquier selector CSS?
No. Stripe publica nombres de clases, estados y pseudoclases permitidos. No admite clases privadas ni relaciones descendiente como .Tab .TabLabel.
15. ¿Puedo usar border-color dentro de rules?
La sintaxis de propiedades se expresa en camelCase, por ejemplo borderColor. Además, la propiedad debe estar permitida para la clase seleccionada.
16. ¿Qué es clientSecret?
Es un secreto de cliente asociado a un PaymentIntent o SetupIntent concreto. Se utiliza para completar ese flujo desde el navegador. No es la clave secreta de cuenta, pero debe tratarse con cuidado y no registrarse ni compartirse.
17. ¿Por qué necesito backend?
Porque operaciones como crear un PaymentIntent y decidir el importe deben realizarse de forma confiable en el servidor. Allí se guarda la clave secreta.
18. ¿Qué significa fontSizeBase?
Es el tamaño tipográfico de referencia del componente. Otras variables de tamaño pueden derivarse de él mediante unidades relativas.
19. ¿Puedo cambiar el diseño del formulario completo?
Puedes personalizar muchos aspectos, pero la disposición interna del Element se mantiene dentro de la estructura que Stripe ofrece. No puedes convertirlo en un componente arbitrario.
20. ¿Por qué no cambia el campo cuando modifico CSS?
Porque el campo pertenece al componente seguro de Stripe y no al DOM normal de tu página. Utiliza Appearance API para los estilos admitidos.
21. ¿Puedo tener tema claro y oscuro?
Sí. Puedes definir dos objetos de apariencia y utilizar uno u otro al crear Elements. El cambio dinámico durante una sesión requiere diseñar la lógica de actualización correspondiente; el ejercicio básico solo selecciona el tema al cargar.
22. ¿Payment Element y Checkout son lo mismo?
No. Payment Element es un componente dentro de una experiencia que construyes. Checkout es una solución de checkout de Stripe con su propia API y opciones de personalización.

Nivel 3 — Avanzado (Preguntas 23 a 33)

23. ¿Appearance API funciona con CardElement?
La documentación de Appearance API indica que no admite Elements individuales de método de pago como CardElement. Para esos Elements se utiliza el objeto Style.
24. ¿Qué API de pago conviene usar: Payment Intents o Checkout Sessions?
Stripe recomienda Checkout Sessions con Payment Element para la mayoría de integraciones nuevas. Payment Intents es adecuado si necesitas controlar todo el flujo, pero exige implementar por tu cuenta más lógica, como impuestos, descuentos, envío y otros aspectos.
25. ¿Puedo aceptar el importe enviado desde el navegador?
No debes confiar en él. El navegador puede ser manipulado. El servidor debe calcular o validar el importe usando datos confiables del pedido.
26. ¿Cómo verifico que un pago se ha realizado de verdad?
Consulta el estado del PaymentIntent en el servidor y utiliza webhooks para recibir eventos de Stripe. No confíes exclusivamente en una respuesta visual del navegador.
27. ¿Qué ocurre si un método de pago requiere redirección?
El flujo puede llevar al cliente a una página externa de autenticación o autorización y devolverlo después a la URL indicada. Debes implementar y probar correctamente la vuelta al sitio.
28. ¿Cómo se cargan fuentes personalizadas?
La opción fonts de la instancia Elements admite fuentes CSS o fuentes personalizadas según el formato documentado por Stripe. Debes alojarlas correctamente, permitir que el navegador las recupere y asignarlas mediante fontFamily.
29. ¿Puedo usar rgba() en todas las variables de color?
No. Stripe especifica que colorPrimary, colorBackground, colorText, colorSuccess, colorDanger y colorWarning no admiten rgba() ni var(--myVariable) como valor directo.
30. ¿Puedo aplicar padding a cualquier selector?
No. Las reglas de Appearance API tienen una lista de propiedades admitidas por clase. Comprueba la tabla oficial antes de utilizar una propiedad.
31. ¿La Appearance API garantiza accesibilidad?
No. Facilita controles visuales, pero la accesibilidad requiere comprobar contraste, foco, legibilidad, teclado y mensajes de error. Una configuración puede ser técnicamente válida y aun así resultar difícil de usar.
32. ¿Qué cambia entre Payment Intents y Checkout Sessions en Appearance API?
La documentación de Appearance API tiene variantes específicas. La página consultada indica que la guía principal trata integraciones con Payment Intents y remite a una guía distinta para Checkout Sessions. No reutilices una integración de confirmación como si ambas APIs fueran intercambiables.
33. ¿Qué necesito antes de pasar a producción?
Como mínimo: integración segura, claves live protegidas, HTTPS, webhooks verificados, importes calculados en servidor, gestión de errores y estados, pruebas de todos los métodos habilitados, revisión de accesibilidad, política de privacidad y obligaciones legales aplicables, monitorización y un procedimiento de soporte y reembolsos. Este curso no sustituye una auditoría técnica ni legal.

20. Buenas Prácticas Profesionales y Anexo Técnico

  • Seguridad: Nunca publiques sk_test_ ni sk_live_; excluye .env de Git; usa HTTPS en producción; nunca aceptes el importe final del navegador como fuente de verdad.
  • Webhooks: Verifica siempre el estado del pago en el servidor mediante webhooks de Stripe antes de entregar productos o servicios.
  • Separación de responsabilidades: Frontend (presenta UI y confirma con Stripe.js) · Backend (decide importe, crea PaymentIntent y valida estado) · Stripe (procesa flujo y comunica eventos).
Principio final: Appearance API no consiste en decorar un formulario. Consiste en integrar un componente de pago seguro en una experiencia de marca sin perder de vista los límites técnicos, la accesibilidad ni la seguridad del dinero del cliente.
